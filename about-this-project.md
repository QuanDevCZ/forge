# About this project

Context from the owner that the code and README don't capture: why Forge exists, who it is for,
what matters, what to avoid. Filled in through an interview (one question at a time); answers
are recorded below as they come in.

## Interview notes

- **Why Forge exists:** the owner just wanted to build it — a personal build project, not a
  reaction to a gap in existing apps.
- **Audience:** only the owner. No other users planned, so a hardcoded week and personal
  defaults are fine; don't add multi-user configurability.
- **Next focus:** polish / UI — visual and interaction improvements to existing screens.
- **Non-negotiable:** honest feedback. The rules engine must never sugarcoat a bad week, even
  when the verdict is unpleasant.
- **UI feel:** game-like — streak, discipline score and debt should feel like real stakes. (Still
  dark-only, and status colours stay paired with text labels per CLAUDE.md.)
- **Working style:** no complaints so far; current approach is fine.
